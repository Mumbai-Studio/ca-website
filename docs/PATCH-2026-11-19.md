# Patch 2026-11-19-patch1

Applied on top of the live full package `2026-11-19-0114-final`. The host receives `CA-website-patch-2026-11-19.zip` (105 site files) and `nginx.conf`.

| Issue | Cause | Fix |
|---|---|---|
| White strip above the header on 1920 × 1080 and other 16:9 or wider screens | The screen-shape flag on `<html>` was called `wide`, the class of the full-width picture band, so the page took the band's 60 px top margin and 80% height | The flag is now `html.scr169` (head script, `site` script, styles) |
| Opening logo seldom animated | The rise (0.6 s) started with the page, before the logo picture arrived; on a first visit the picture simply appeared | The head script marks `#pl.ready` when the picture arrives; the rise (1.2 s) and the line (1.0–2.3 s) start then, and the 3.25 s hold counts from then (at most 1.5 s is waited) |
| Sandy Hook gallery showed a section and a sketch | Browsers kept the October launch's pictures, which had the same file names (`p01` was a section, `p03` a sketch), for 30 days | `p01`–`p04`, `sketches` and `c01-t` renamed `…r2`; the data already sorted photos, drawings and the sketch GIF correctly |
| Phone scroll too fast | A flick landed on the next section in 0.3 s | Touch swipes glide in 0.7–1.15 s (`springTo` "soft" mode); wheel, keys and sliders unchanged |

The new head script changes the Content-Security-Policy hash: `sha256-82AwgoR/TRkX92d7lf5f4CyUZ9Hw039ex9zYKrVMk7M=` replaces `sha256-ng9YpkHLx0jG2Df8NFUsL8MTsE+cpwbvjdQX1CcEXYM=` in `.htaccess`, `_headers` and `nginx.conf`.

**Rule for later uploads:** a picture whose content changes gets a new file name. Pictures are cached for 30 days, so a replacement under the same name is not seen by returning visitors.
